# LLM Security Daily 设计规格

**日期：** 2026-08-02  
**状态：** 已确认方案，待用户复核书面规格  
**执行环境：** 本机 macOS  
**计划时间：** 每天 06:00（Asia/Shanghai）  
**模型：** MiniMax-M3，最高可用推理强度（Codex 配置中的 `high`，对应本任务所称 max）

## 1. 目标

每天自动检索、筛选并阅读 5 篇高质量 LLM Security 论文，通过 Notion MCP 将每篇论文写成一条独立的中文 Notion 笔记。覆盖范围同时包括：

1. **LLM 自身安全研究**：越狱、提示注入、后门、数据投毒、隐私泄漏、模型窃取、幻觉、Agent 安全、工具调用安全、供应链安全、对齐与防御等。
2. **LLM 用于安全研究**：漏洞发现、代码审计、恶意软件分析、网络攻防、威胁情报、数字取证等。

长期保留物是 Notion 中的论文笔记。本地不得长期保留下载的 PDF 或论文正文缓存。

## 2. 范围与非目标

### 2.1 本期范围

- 使用本机 `launchd` 调度。
- 使用 `codex exec` 启动 MiniMax-M3 Agent。
- 使用现有论文检索能力和公开论文元数据源寻找候选论文。
- 必要时下载公开可访问的 PDF 进行全文核验。
- 使用 Notion MCP 创建数据库、查询既有记录、去重并写入笔记。
- 对调度、互斥、退出状态、日志和缓存生命周期进行控制。

### 2.2 非目标

- 不部署云服务器，也不保证电脑关机时仍能在 06:00 准时执行。
- 不绕过付费墙、登录限制、验证码或访问控制下载论文。
- 不创建每日汇总页、邮件通知或其他未提出的输出渠道。
- 不在本地建立永久 PDF 论文库。
- 不修改现有的 `notion-minimax-bridge` 项目。

## 3. 方案概览

采用“轻量调度器 + Codex Agent”架构：

1. `launchd` 在每天 06:00 触发本地启动脚本，并在登录或唤醒后支持一次补跑检查。
2. 启动脚本取得单实例锁，防止同一天并发执行。
3. 启动脚本在固定缓存根目录下创建唯一的本次运行目录。
4. Agent 在该运行目录中搜索候选论文、读取必要 PDF、评分并生成 5 篇笔记。
5. Agent 通过 Notion MCP 查询数据库，执行跨日去重和幂等写入。
6. 启动脚本记录必要的运行结果，然后在 `finally`/退出陷阱中删除本次运行目录。
7. 下次启动前，仅清理由本系统创建、且超过 24 小时的异常残留运行目录。

Agent 的工作目录就是本次运行目录，并以 `workspace-write` 沙箱运行。这样即使 Agent 需要写入文件，也只能将 PDF 和临时分析写入专属缓存空间；项目脚本、用户下载目录和其他论文目录不在其可写工作区内。

## 4. 数据流

### 4.1 候选发现

候选来源包括但不限于：

- AI 顶会：AAAI、NeurIPS、ICML、ICLR、ACL、EMNLP。
- 网络安全顶会：IEEE Symposium on Security and Privacy、USENIX Security、ACM CCS、NDSS。
- arXiv。
- 用于交叉验证元数据的 DBLP、OpenReview、OpenAlex、Semantic Scholar、Crossref 等公开索引。

搜索词会覆盖 `LLM security`、`large language model security`、`prompt injection`、`jailbreak`、`LLM privacy`、`LLM backdoor`、`agent security`、`LLM vulnerability detection` 等主题，但不会仅以关键词命中作为质量依据。

### 4.2 每日来源覆盖

每天最终 5 篇尽量满足：

- 至少 1 篇 AI 顶会论文；
- 至少 1 篇网络安全顶会论文；
- 至少 1 篇 arXiv 论文；
- 剩余 2 篇按综合质量排序选择。

同一工作同时存在会议版和 arXiv 版时合并为一篇，以可核验的正式会议版本作为主记录，并保留 arXiv/PDF 链接。若某一类别因来源暂时不可用而无法满足，系统应扩大检索时间窗口并重试；不得用明显不相关或低质量论文机械凑数。

“每天 5 篇”不等于“当天发表 5 篇”。系统优先选择近期论文；候选不足时，从近年尚未收录的高质量论文中补足。

### 4.3 质量评分

候选论文按以下维度进行 100 分制评价：

- LLM Security 直接相关性：30 分；
- 方法、威胁模型或安全应用场景的清晰度：20 分；
- 实验完整性，包括基线、消融、数据集和指标：20 分；
- 会议质量或 arXiv 论文的证据充分程度：15 分；
- 新颖性与现实安全影响：10 分；
- 元数据、全文和结果的可核验性：5 分。

笔记中记录评分及简短理由。引用量只作为辅助信号，不以高引用量替代内容审查。近期 arXiv 论文不能因尚无引用而被自动判为低质量。

## 5. 去重与幂等性

Notion 数据库是论文去重的事实来源，不另建包含论文正文的本地数据库。

去重键按以下优先级确定：

1. DOI；
2. arXiv ID（忽略版本号）；
3. 规范化论文标题。

规范化标题仅用于兜底：转为小写，统一空白和常见标点。会议版与预印本标题存在轻微变化时，Agent 必须结合链接和摘要判断是否为同一工作。

每日执行开始时查询 Notion：

- 若当天已有 5 条成功记录，直接成功退出；
- 若当天只有部分记录，只补足到 5 条；
- 写入前再次按唯一标识查询，避免重试造成重复；
- 单篇页面必须先完成内容生成和校验，再写入 Notion；
- Notion 写入发生部分失败时，下一次重试只补缺失记录。

## 6. Notion 设计

创建一个工作区级私有数据库 **“LLM Security Daily”**。每篇论文是一条数据库记录，页面正文就是完整笔记。

### 6.1 数据库属性

- `论文标题`：Title
- `收录日期`：Date
- `发表日期`：Date
- `来源类型`：Select（AI 顶会 / 安全顶会 / arXiv）
- `会议或来源`：Select 或 Rich text
- `研究类别`：Multi-select（LLM 自身安全 / LLM 用于安全）
- `主题标签`：Multi-select
- `质量评分`：Number
- `论文主页`：URL
- `PDF`：URL
- `唯一标识`：Rich text

如 Notion MCP 对某一属性类型有限制，允许采用功能等价的 Rich text，但不得删除标题、收录日期、来源、评分、链接和唯一标识这些核心字段。

### 6.2 页面正文模板

每篇中文笔记包含：

1. 一句话结论；
2. 研究问题与背景；
3. 威胁模型或安全应用场景；
4. 核心方法；
5. 实验设置；
6. 关键结果及原文依据；
7. 主要贡献；
8. 优点；
9. 局限与可能失效条件；
10. 对 LLM Security 研究的启示；
11. 可复现性与代码情况；
12. 论文主页、PDF、代码等可核验链接。

关键数值必须能在论文正文、表格或官方元数据中核验。无法确认的信息写明“论文未说明”或“未能核验”，禁止猜测。不得把搜索结果摘要当作已阅读全文的证据。

## 7. PDF 与缓存安全设计

本节是不允许弱化的安全约束。

### 7.1 唯一允许的缓存位置

固定缓存根目录：

```text
~/llm-security-digest/cache/
```

每次运行由调度器使用安全临时目录 API 创建：

```text
~/llm-security-digest/cache/run-<随机标识>/
```

PDF 使用程序生成的文件名，如 `paper-01.pdf`，不直接使用论文标题作为路径。下载前限制单个文件大小，下载后检查 PDF 响应类型或 `%PDF-` 文件头；不符合要求的内容立即视为下载失败。

### 7.2 删除安全不变量

清理代码只能删除“本次运行目录”或缓存根目录的合格直接子目录，并且删除前必须同时满足：

1. 缓存根目录的规范化绝对路径等于项目预设路径；
2. 缓存根目录不等于 `/`、用户主目录、项目根目录或空路径；
3. 待删除目录的规范化父目录严格等于缓存根目录；
4. 待删除目录名以 `run-` 开头；
5. 待删除对象不是符号链接；
6. 待删除路径不等于缓存根目录本身；
7. 过期清理只枚举缓存根目录的直接子目录，不递归搜索其他位置。

实现不得使用宽泛 shell 删除命令、通配符删除、`find -delete`，也不得根据用户输入或论文标题拼接删除路径。清理应由受测试的 Python 函数调用 `shutil.rmtree` 完成，Agent 本身不负责执行删除命令。

### 7.3 生命周期

- 正常完成：在退出前删除本次运行目录。
- Agent、网络或 Notion 失败：仍在 `finally` 中删除本次运行目录。
- 进程被强制终止或机器掉电：目录可能残留；下一次启动仅删除满足全部路径检查且修改时间超过 24 小时的 `run-*` 直接子目录。
- PDF、提取文本和中间分析均不得复制到日志或项目其他目录。

### 7.4 安全测试

自动化测试必须至少验证：

- 正常运行目录可被删除；
- 缓存根目录本身不能被删除；
- 缓存根目录之外的目录不能被删除；
- 不以 `run-` 开头的目录不能被删除；
- 指向外部目录的符号链接不能被跟随或删除目标；
- 过期清理不触碰缓存根目录之外的哨兵文件；
- Agent 失败时仍清理本次运行目录；
- 24 小时以内的运行目录不会被过期清理。

## 8. 调度、补跑与并发

安装用户级 `launchd` LaunchAgent：

- `StartCalendarInterval`：Hour = 6，Minute = 0；
- `RunAtLoad`：启用，但启动脚本在 06:00 前只做无副作用检查并退出；
- 明确设置 `TZ=Asia/Shanghai`；
- 使用单实例文件锁，防止 06:00 触发与唤醒补跑重叠；
- 每次执行先检查 Notion 当天已存在的记录数，以实现补跑和幂等。

如果 Mac 在 06:00 睡眠，任务在唤醒后补跑；如果关机，则在之后登录并加载 LaunchAgent 时补跑。该设计不更改电源管理设置，也不自动唤醒电脑。

## 9. Agent 权限边界

每日 Agent 使用：

- 模型：`MiniMax-M3`；
- 推理强度：`high`（本环境可用的最高等级）；
- 沙箱：`workspace-write`；
- 工作目录：本次 `run-*` 临时目录；
- Notion MCP：仅用于目标数据库的创建、查询和页面写入；
- 网络：仅访问论文检索、论文主页、公开 PDF 和必要元数据服务。

Agent 提示词明确禁止：

- 删除任何本地文件或目录；
- 写入运行目录以外的位置；
- 修改已有 Notion 页面，除非是本任务创建且处于未完成状态的论文记录；
- 下载与论文核验无关的文件；
- 暴露或记录令牌、凭据及其他敏感信息。

清理由父调度器负责，避免让生成式 Agent 决定删除目标。

## 10. 日志与隐私

只保留运行所需的最小日志：开始时间、结束时间、候选数量、成功写入数量、失败来源和退出状态。日志不得包含 PDF 正文、Notion 凭据、访问令牌或其他敏感信息。

日志采用固定大小轮换或保留有限天数。日志清理只针对项目预设日志目录中的固定日志文件，不与 PDF 缓存清理共用逻辑。

不得将本机文件名、账户信息或连接凭据写入 Notion 论文笔记。

## 11. 失败处理

- 单个检索源失败：记录来源错误，继续使用其他来源；必要时扩大时间窗口。
- PDF 不可合法下载：使用官方摘要和元数据，但笔记明确标注“未核验全文”；若证据不足，不选入最终 5 篇。
- MiniMax-M3 运行失败：不写入未完成笔记，清理缓存并返回失败状态。
- Notion MCP 暂时失败：保留 Notion 中已成功创建的完整笔记；下次运行通过唯一标识补足，不重复写入。
- 多次失败不会触发删除项目外文件，也不会保留 PDF 作为恢复手段。

## 12. 验收标准

实现完成必须满足：

1. 手动触发一次后，Notion 数据库中出现 5 条不重复的完整中文论文笔记。
2. 5 篇论文覆盖 LLM 自身安全与 LLM 用于安全两个研究范围，且满足来源覆盖规则或明确记录无法满足的真实来源故障。
3. 所有关键元数据和结果均可通过官方页面或论文正文核验。
4. 使用 MiniMax-M3 的最高可用推理强度完成筛选与写作。
5. 运行结束后，本次 `run-*` 目录和其中 PDF 不存在。
6. 缓存根目录之外的测试哨兵文件在正常、失败和过期清理场景下均保持不变。
7. 第二次手动触发不会重复创建已有论文，只补足当天缺失数量或直接成功退出。
8. `launchd` 已加载，并配置为每天 06:00（Asia/Shanghai）运行。
9. 项目不包含令牌、API 密钥、PDF 或论文正文缓存。
